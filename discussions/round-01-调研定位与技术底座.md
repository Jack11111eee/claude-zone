# 讨论稿 Round 01 — 调研、定位与首批拍板

- 日期：2026-09-07
- 状态：✅ 已收口（结论已进入 Round 02）
- 参与方：用户 + Claude

## 1. 痛点陈述

Claude Code 原生会话管理（`/resume`）按项目目录组织所有会话，无任务性质维度的区分。导致：

- 杂活与核心任务混在同一列表；
- 会话间上下文交叉污染，结果偏移；
- 讨论、构建、版本维护各自需要的行为模式无法隔离（讨论不该动手改代码、维护不该误触 force-push）。

## 2. 生态调研结论（2026-09-07 核实）

| 工具 | ~Stars | 定位 | 与本方案的关系 |
|---|---|---|---|
| github/spec-kit | 133k | 规格驱动开发（specify→plan→tasks→implement） | 覆盖"讨论→实施交接"，但按**工作流阶段**切、文档重型、绑定自家体系 |
| BloopAI/vibe-kanban | 28k | 看板 + git worktree 管理并行 agent 会话 | 按**并行空间**切，不按任务性质切 |
| thedotmack/claude-mem | 93k | hooks 全量记忆 + 自动压缩注入 | **反面教材**：全量自动注入 = 本方案要解决的上下文污染本身 |
| mcpware/cross-code-organizer | 375 | 会话/配置总控 dashboard | GUI 外壳，无工作流语义 |
| loocor/codemate | 667 | macOS 原生 app 管理 CLI AI 会话 | GUI 外壳，不分区 |
| siteboon/claudecodeui 等 | — | 会话查看/追踪 | "看会话更方便"，与分区无关 |

**空档（本项目定位）**：无人按**任务性质**切分会话，无人把**区分区之间的交接**当作一等公民。
差异化坐标：区（任务性质）× 行为画像（护栏）× 显式交接（handoff），三者同时成立。

## 3. 用户原始构想（存档）

四分区：**杂活区**（简单、朴素、一条线、明确）、**核心区**（复杂、非线性、可能引出更多问题）、**讨论区**（构建前规划、修 bug 发现更多问题时回炉讨论）、**版本管理区**（分支 merge、add、gitignore、远程等）。
链接机制原始两方案：a) LLM 预判意图自动开新会话；b) 开新会话时弹框询问是否索引对话。

## 4. 三项修正（Round 01 提出）

1. **升级机制**：杂活/核心边界是活的。会话开始前判不准任务性质，需要"升级"路径（杂活中发现架构问题 → 打 handoff 包去讨论区/核心区），本质是链接机制的复用。
2. **版本管理区拆半**：收尾性 git（commit/push/PR）留在工作会话内完成；维护性 git（分支大扫除、gitignore、远程、tag）才值得独立会话。→ 本区仅指后者。
3. **链接机制第三方案**：退出时产物（handoff 文档，模型在上下文完整时主动写出）+ 进入时指针（新会话探测未消费 handoff，人确认后注入）。拒绝"索引对话全文"（= claude-mem 模式）。意图预判不做——模型可建议，永不代办。

## 5. 技术底座事实（官方文档逐页核实，v2.1.263，2026-09-06）

- `/resume` picker 能力强于预期：`/` 搜索、Space 预览、Ctrl+R 改名、Ctrl+A/W/B 跨项目/worktree/分支过滤、fork 分组、AI 标题。**但插件不可修改其 UI**（无扩展点，完整文档负证据）。
- 会话内开新会话的官方路径（v2.1.212+）：`/fork [prompt]`（复制到新后台会话）、`/bg`、`claude --bg --name`、深链 `claude-cli://open?q=<prompt>&cwd=<路径>`（新终端，预填不发送）。
- `SessionStart` 会话开始时自动重跑（含 compact 后重注入），可经 `additionalContext` 注入（~10k 字符上限）。
- `UserPromptSubmit` 每条用户消息前触发，可注入 `additionalContext`、可写 `sessionTitle`。
- `SessionEnd` 无 TTY、默认 1.5s（上限 60s）→ 只适合轻量登记，**不适合事后 LLM 分类**。
- `AskUserQuestion` 仅交互式可用 → 适合做"确认注入"弹框，但hook里不可用；确认逻辑须在 skill/command 内进行。
- SDK 有 `tag_session()` 持久 tag，但 CLI 无入口、picker 不显示 → 不依赖，用本地 sidecar。
- 会话 JSONL 为 internal 格式（版本可变）、默认 ~30 天清理 → sidecar 索引须自存标题/摘要快照，防指针悬空。
- 命名会话 `-n`/`--name` 可被 `claude --resume <name>` 直接命中，picker 中显示。
