# Phase 9 Plan 09-01: Bash 护栏加固

**Goal**: maint Bash 黑名单补齐两个已实测确认的绕过面（真 bin 复跑证实），既有裁决不动。

**实测缺口（2026-09-08 主会话 ZONING_HOME 隔离实测，全部 allow）:**

| 形态 | 现正则 | 结果 | 原因 |
|---|---|---|---|
| `git clean -Xfd` | `git clean\s+.*-f` | MISS | `-Xfd` 里无独立 `-f` 子串（X 在 f 前） |
| `git clean -xfd` | 同上 | MISS | 同上 |
| `git  clean -Xf`（双空格） | `git clean\s+.*-f` | MISS | `git clean` 字面单空格，双空格不匹配字面前缀 |
| `git push origin main --force-with-lease` | 见下 | allow | **预期行为**（GUARD-04 保护性操作放行——回归锚点，不是缺口） |

`git\s+clean` 对双空格实测命中——缺的是「clean 前的字面 `git clean`（单空格）+ 后续 `-f` 在组合旗标内」两面。

**方案（收紧两条正则，保守增量）：**

1. `git clean` —— `git clean\s+.*-f` → `git\s+clean\s+.*-[a-zA-Z]*f`
   - 拦：`-f`、`-Xf`、`-fx`、`-Xfd`、`-xfd`（组合旗标含 f 即拦——git clean 的 f 永远意味着删文件，保守面正确）
   - `-[a-zA-Z]*f` 只吃字母旗标串，不误伤（如 `git clean -n` 干跑不受影响）
2. `git push --force` 家族 —— `git push\s+.*--force(?!\S)` 保持不动（已精确），但补双空格面：`git\s+push\s+.*--force(?!\S)`
   - 同理 `git\s+reset\s+--hard`、`git\s+branch\s+(-D|--delete --force)`、`git\s+reflog\s+expire`、`git\s+gc\s+--prune=now`、`git\s+checkout\s+\S+\s+--\s`（统一 `git\s+` 前缀，一处规律）
3. **测试矩阵固化**（GUARD-06）：bin 层独立测试脚本（ZONING_HOME 隔离），三组：
   - 新拦截组：`-Xfd`/`-xfd`/`-Xf`/双空格全家（每条一个用例，含 `git  clean -Xfd` 交叉）
   - 回归十用例：v1.0 原矩阵全过（含 force-with-lease 放行、`git clean -n` 仍 allow、非 maint 区不拦）
   - 边界：`git clone -Xfd`（clean 前有其他词）不拦——`git\s+clean` 锚定
4. zones/maint.yaml 单引号标量纪律不变（YAML 转义踩过的门）

## Tasks
