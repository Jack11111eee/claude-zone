# Phase 8 Plan 08-01: SessionEnd lastSeen

**Goal**: DESIGN §9「轻量更新 lastSeen（append 事件）」从 stub 变实：会话结束追加一条轻量事件，`zone list` 的相对时间以 session/lastSeen 中最新者为准。

**Design Anchors:**
- `hooks/session_end.py` —— 当前 `sys.exit(0)` 占位 stub
- `bin/zone` `replay_sessions`（~L300）—— 同 key 后事件即现值；`_replay_handoffs` 有 field-merge 先例（title 保留）
- `bin/zone` `cmd_list` —— `rows.sort(key=ts)` 排序用 session 事件 ts；相对时间渲染 `relative_time(r["ts"])`
- 事件契约（§7.1/§7.2）：append-only、同键 last-event-wins、无删除

**方案：**

1. **bin：新内部子命令 `_touch`**
   - `zone _touch` 读 stdin JSON（hook payload：session_id、cwd）→ 判区（按 sessionId 在索引里查现值，复用 `_guard_resolve_zone` 的判区思路或直接 replay_sessions 查）
   - 已登记（四区）→ append `{"type":"session","kind":"lastSeen"}` 事件：**同 session 事件 schema，kind 标记**（重放天然 last-wins，`cmd_list` / `replay_sessions` 无需改即可让 ts 更新到最新）
   - unzoned / 未登记（GRACE 相同口径：SESS-02）→ 不 append、不输出
   - 事件 body 保持轻量：`v/ts/type/sessionId/zone/title(继承)/cwd/source:"session_end"`
2. **hook：session_end.py 薄封装**
   - stdin JSON 转发 `zone _touch --json`（与 session_start.py 的 `_register-session` 同构）；bin 失败静默 exit 0（SessionEnd 绝不能阻塞/报错）
3. **list 相对时间（如需）**
   - 设计核实：`replay_sessions` 覆盖即最新 ts —— 若 lastSeen 复用 type:"session"，`list` 行为自动正确。**若** lastSeen 用 type:"seen" 独立键，则 `cmd_list` 行的 ts 取 max(session.ts, latest seen.ts)。优先前者（零改动面），tasks 里以实测定案
4. **验收测试**
   - ZONING_HOME 隔离：登记一个 core 会话（_register-session 手工造）→ 模拟 SessionEnd payload 跑 hook → index.jsonl 多一条 kind:lastSeen → `zone list` 该行相对时间为「刚刚」
   - 造 unzoned 会话 SessionEnd → 事件数不变（零打扰）
   - 两次 SessionEnd → 两条 lastSeen（append-only 语义），list 仍一行（last-wins）

## Tasks

1. bin `_touch` 子命令（判区 + lastSeen append + unzoned 静默）
2. session_end.py 薄封装转发（失败静默）
3. list 相对时间核实（预期零改动；若改，只动 ts 取值一行）
4. 验收测试 4 用例（上列）+ `zone doctor` 不把 lastSeen 当异常
